## 1. `fig01_pipeline` 评测流程总览（已完成）

> 已按本节制作完成，原图为项目根目录 `figures/四阶段音频评估流程图.png`。放入报告的 `docs/report_tex/figures/fig01_pipeline.png` 修正了原图两处错字："首听"→"盲听"，"仅看静始轨"→"仅看原始轨"；并按报告口径（H1 不再拆分）将"H1a 脚步增强有效"改为"H1 脚步增强有效"。

**目的**：一张图讲清楚"数据从哪来 → 脚步由谁认定 → 怎么比 → 得出什么结论"，是读者理解整份报告的入口。正文 1.3 节称评测遵循四项原则：同源配对、事件级测量、真值由人确定、混杂受控。这四项原则就是本图的主线，每一栏对应回答一个质疑：

| 栏 | 回答的质疑 |
|---|---|
| ① 同源三轨采集 | 比较公平吗？——三个版本来自同一段声音，差别只来自处理方式 |
| ② 事件检测与标注 | 哪些是脚步、谁说了算？——以人工判断为准，模型只扩展人工标注 |
| ③ 对比与对照 | 增益真是 FPS AI 带来的、且不同于 EQ 吗？——产品主对比 + 机制性对照 |
| ④ 假设检验与结论 | 结论是什么？——各假设的判定结果 |

**版式**：横向四栏（泳道或四个大圆角框），从左到右，栏间用粗箭头连接；每栏顶部为栏名（黑体 9 pt），栏内为 2–4 个小框，自上而下用细箭头串联。

| 栏 | 栏名 | 栏内元素（自上而下） |
|---|---|---|
| ① | 同源三轨采集 | ⓐ 游戏实录片段：VALORANT 16 段 / PUBG 15 段，共 7.7 min，48 kHz 立体声 → ⓑ 同一段素材录三个版本：**原始**（AI、EQ 均关）、**FPS AI**（仅开 AI）、**实际 EQ**（仅开 EQ，即 C3 产品预设：10 段峰值 EQ）→ ⓒ 同源性验证：三轨互相关对齐，偏移 0 样本；EQ 实测频响与理论偏差 ≤ 0.03 dB |
| ② | 事件检测与标注 | ⓐ 原始轨谱通量起点检测 → **1620 个候选事件**（三轨用同一时间窗）→ ⓑ 人机协同标注：4 轮、**348 条人工标注**（盲听，看不到处理轨）＋ 标注模型（AST + CLAP 线性探针，只看原始轨）扩展到其余事件 → ⓒ 输出标签：脚步 / 枪声 / 其他（换弹、道具等）；拿不准的 110 个（6.8%）排除 |
| ③ | 对比与对照 | ⓐ 事件增益 G = 20·log₁₀(RMS_处理 / RMS_原始)（同一时间窗）→ ⓑ **产品主对比**（粗框、最醒目）：原始 vs C3 实际 EQ vs C3 FPS AI → ⓒ **机制性对照**（细框，标"辅助"）：同电平比较 ΔG（±3 dB 内与脚步配对）、匹配静态 EQ（脚步增益与 FPS AI 相同的固定滤波器）→ ⓓ 统计：按片段聚类自助法 95% CI |
| ④ | 假设检验与结论 | 顶部一个结论小框："产品主对比：脚步 FPS AI +8.7 dB / 实际 EQ −0.8 dB；枪声 +0.2 / −1.0 dB"；其下四个假设小框纵向排列，每框右侧标判定徽标：**H1 脚步增强有效**（✓ 支持）/ **H2 事件选择性（核心）**（✓ 支持，框线加粗）/ **H3 非目标声音保持性**（✓ 支持）/ **H4 稳定性**（✓ 支持） |

**细节**：
- 栏①三个版本用三种颜色（原始 `#333333`、FPS AI `#1F4E79`、实际 EQ `#8C8C8C`）的三条平行细线表示"三轨"，三条线一直延伸到栏②，表示同一时间窗在三轨上取样。
- 栏②中"人工"模块用浅橙底，"模型"模块用浅蓝底，与图 3 保持一致；人工模块旁标"人工标注优先"。

- 栏④徽标颜色：支持 ✓ 绿 `#2CA02C`、部分支持 ◐ 橙 `#E69F00`。
- 底部加一条细灰带，标注四项原则："同源配对 · 事件级测量 · 真值由人确定 · 混杂受控（同电平匹配、按片段聚类统计）"。

## 2. `fig04_model` 标注模型结构（已完成）

> 已按本节制作完成，原图为项目根目录 `figures/双分支音频分类流程图.png`。放入报告的 `docs/report_tex/figures/fig04_model.png` 修正了原图 AST 支路 PCA 维数的错误："760"→"130"。

**目的**：清楚展示"冻结的大模型只做特征提取、只训练极少量参数"的设计，回应"几百条标注够不够训练"的质疑。

**版式**：自左向右的数据流图，**上下两条并行支路**（上 AST、下 CLAP）在右侧汇合。全图宽 160 mm，高约 80–90 mm。冻结模块灰底 + 雪花/锁图标，可训练模块浅绿底；每个模块下方用 6.5 pt 灰字标注张量形状。

### 2.1 输入（最左）
- 框："原始轨音频（48 kHz，双声道 → 单声道）"
- 下方小字："以检测到的事件起点 t 为中心截取"
- **电平归一化**模块（所有支路共用）：每个片段 RMS 归一到 0.05。旁注："消除响度信息，避免模型借音量区分脚步，保证后续同电平比较不循环"

### 2.2 上支路：AST（Audio Spectrogram Transformer）
按顺序：
1. **截窗**：[t − 0.3 s, t + 0.7 s]，共 1 s
2. **重采样**：48 kHz → 16 kHz
3. **对数 Mel 滤波器组**：128 Mel 带 × 128 帧（10 ms 帧移）→ 形状 `128 × 128`
4. **图块切分**：16 × 16 图块，步长 10 → 12 × 12 = **144 个图块**；位置编码在时间方向截断（原模型为 1024 帧）
5. **AST 编码器（冻结 ❄）**：12 层 Transformer，768 维，AudioSet 预训练（`MIT/ast-finetuned-audioset-10-10-0.4593`），约 8.6 × 10⁷ 参数
6. **池化**：取最后一层 144 个图块向量的均值（不含 CLS / 蒸馏两个 token）→ `768`
7. **标准化**（StandardScaler）→ **PCA**（保留 95% 方差）→ `130`
8. **L2 逻辑回归**（可训练，C = 0.05，类别平衡）→ 概率 p_AST；参数量 130 + 1 = **131**

### 2.3 下支路：CLAP（HTSAT 音频编码器）
1. **双窗截取**（两个并列小框）：紧窗 [t − 0.05 s, t + 0.35 s] 与长窗 [t − 0.5 s, t + 0.5 s]，各自 RMS 归一化
2. **CLAP 音频编码器（冻结 ❄）**：HTSAT，48 kHz 原生输入（`laion/clap-htsat-unfused`），两窗共享同一编码器（画成一个编码器、两路输入，或两个框之间标"共享权重"）
3. **音频投影嵌入**：每窗 `512` → **拼接** → `1024`
4. **标准化 → PCA（95% 方差）** → `78`
5. **L2 逻辑回归**（可训练，C = 0.05，类别平衡）→ 概率 p_CLAP；参数量 78 + 1 = **79**

### 2.4 融合与判定（右侧）
1. **概率平均**：p = (p_AST + p_CLAP) / 2（画成两条支路汇入一个 "Σ/2" 圆形节点）
2. **三区间判定**（画成一根 0–1 的竖直或水平概率条，分三色）：
   - p ≥ 0.8 → 判为脚步（`#4C9BE8`）
   - 0.2 < p < 0.8 → 不确定，排除（浅灰）
   - p ≤ 0.2 → 判为非脚步（`#D62728`）
3. **人工覆盖**：上方用虚线框"人工标注（348 条）"指向判定结果，标"人工标注优先"

### 2.5 图内必须出现的说明
- 图例：❄ 冻结（不训练） / 浅绿 可训练
- 右下角小表或文字框：
  - "监督分类器参数：131 + 79 = **210**"（AST/CLAP 主干冻结；StandardScaler 与 PCA 为无监督拟合，不计入）
  - "训练样本：332 条明确人工标注（第 1 轮 147 条）"
  - "留片段 5 折交叉验证 AUC：AST 0.840 / CLAP 0.817 / 集成 **0.891**（第 1 轮随机样本）"
- 训练范围用浅绿虚线框圈出（只包含两个逻辑回归 + 标准化/PCA 拟合），框旁标注"仅此部分使用人工标注拟合"

### 2.6 不要画的内容
- 不要画 Transformer 内部的注意力细节（用一个带"×12"的长方块表示即可）
- 不要出现 FPS AI / EQ 轨：标注模型**只看原始轨**，这是盲法的一部分，可在输入框旁注明"仅原始轨"
